# Tutorial quality rubric

Score each dimension 1–5 and cite evidence (timestamps or quoted lines). End with
one overall verdict: **solid**, **usable with caveats**, or **needs rework**.

## 1. Clarity (1–5)
- Is each step stated as a single, unambiguous action?
- Are terms defined before they are used?
- Is the audio/transcript intelligible and jargon appropriate for the audience?

## 2. Completeness (1–5)
- Are prerequisites and setup stated up front (versions, tools, accounts)?
- Does the video cover the full path from start to a working result?
- Are exact commands, values, and file paths shown rather than implied?

## 3. Correctness signals (1–5)
- Do steps appear in a runnable order with no missing dependencies?
- Are there visible errors, retries, or "it just works" jumps that hide steps?
- Are versions or APIs likely to be current, or flagged as possibly outdated?

## 4. Structure and pacing (1–5)
- Strong hook and a clear statement of the end result in the first 15 seconds.
- Logical chapters; no long tangents or dead air.
- Recap or summary of what was accomplished.

## 5. Accessibility (1–5)
- Captions/subtitles present and accurate.
- On-screen text readable; commands legible.
- Resources (repo, links, sample files) referenced and available.

## Verdict
- Overall score (average or weighted) and the single verdict.
- Top 3 fixes that would most improve the tutorial.
- If reproducing the tutorial as desk work, note the deliverables and a rough
  route (Explore → Choose → Control → Ship → Repair → Finish → QA).
